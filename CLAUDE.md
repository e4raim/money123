# money123 — Рабочая панель (риелторский трекер объектов)

Одностраничное веб-приложение без сборки: чистый HTML/CSS/JS в одном файле,
подключено к Firebase (Realtime Database + Auth) с оффлайн-фоллбеком на
`localStorage`. Никакого npm/bundler для самого приложения — открывается
прямо в браузере.

## Файлы репозитория

| Файл | Что это |
|---|---|
| `index.html` | **Основное приложение** — «Рабочая панель». Объекты недвижимости (продажа/аренда), владельцы, статусы переговоров, сделки, задачи (вкладка «Today»), архив, схема (планировка), гостевой режим. Это то, что нужно редактировать. |
| `Last.html` | Более ранняя версия панели. Держим для истории/сравнения, в работу не берём. |
| `Ddd.html`, `Qqq.html`, `Rrr.html` | Отдельный инструмент «Актуалка — объекты с другими агентами»: список объектов + импорт выписок ЕГРН, свой Firebase-путь (`actualka`). Разные версии одного и того же инструмента. |

Если непонятно, с каким файлом работать — по умолчанию это `index.html`.

## Как устроено приложение (index.html)

- **Хранилище**: Firebase Realtime Database (`diff-1822e`), путь `actualka`
  для объектов, `sessions/`, `aux/devices/`, `aux/loginLog` — для контроля
  сессий/устройств. Если Firebase недоступен — работает на `localStorage`.
- **Auth**: Firebase Auth (email/password), есть гостевой режим
  (`body.guest` скрывает вкладки БД/схемы/сделок и владельца-only поля),
  контроль простоя (`idleMins`) и алерт при входе с нового устройства
  (`checkDeviceAlert`).
- **Данные объекта**: статус переговоров с владельцем — `works` (зелёный),
  `thinking` (жёлтый), `refusal` (красный), `base` (серый); тип сделки —
  продажа/аренда (`deal-badge`); бейдж оплаты, бейдж задач (`todo-badge`).
- **Вкладки** (`viewActualka`, `viewToday`, `viewSchema`, `viewDb`,
  `viewDeals`, `viewArchive`, `viewSettings`): список объектов, план на
  сегодня/календарь, схема дома, база (полный список), сделки, архив,
  настройки.
- **Тема**: светлая/тёмная через `body.dark` + `prefers-color-scheme`,
  переменные в `:root`.
- **Приватность**: класс `body.privacy` скрывает ФИО владельцев/контакты в
  UI (для демонстрации экрана посторонним).

## Важно про безопасность

`FIREBASE_CONFIG.apiKey` зашит прямо в HTML — это ожидаемо для клиентского
Firebase SDK (ключ не секрет сам по себе), но это означает, что **вся
защита данных держится на Firebase Security Rules** в проекте `diff-1822e`.
Если меняешь структуру данных (`actualka/...`, `sessions/...`) — не забудь,
что правила БД должны соответствовать новой структуре. Сами правила в этом
репозитории не хранятся — проверяются в консоли Firebase.

## Разработка

- Правки вноси прямо в `index.html` (или в `Ddd/Qqq/Rrr.html`, если это
  «Актуалка»). Файл большой (~3.5к строк) — используй поиск по `id=` и
  имени функции, а не построчное чтение целиком.
- Открыть локально: `npx http-server .` (или просто открыть файл в
  браузере — но тогда Firebase может блокировать `file://` origin,
  надёжнее через http-server).
- Смоук-тест: `npm install && npm test` (см. `tests/smoke.spec.js`).
  Тест открывает `index.html` в Chromium и проверяет, что панель
  рендерится без ошибок в оффлайн-режиме (без реального Firebase).
- Чек-лист доступности перед сдачей UI-правок: `A11Y-CHECKLIST.md`.
- Заметки/решения между сессиями — `.claude/MEMORY.md`. Перед началом
  работы стоит туда заглянуть, после значимых решений — дописать.

## Конвенции

- Комментарии в коде — только там, где неочевидно (обход бага Firebase,
  причина странного z-index и т.п.), не пересказывать код словами.
- Не вводить bundler/фреймворк ради одной фичи — проект осознанно остаётся
  одним HTML-файлом на чистом JS.
- Цветовые переменные (`--ok`, `--think`, `--no`, `--base` и их `-t`/`-s`
  варианты) уже подобраны под контраст 4.5:1 — если меняешь статус-цвета,
  сохраняй обе версии (для текста и для заливки под белым текстом).
